Swagger
시스템 아키텍처 및 데이터 흐름 개요 — 원본 음성이 최종 STT 결과가 되기까지 거치는 5단계와 실제 폴더
경로는 아래 디렉터리 의 현재 설정값을 그대로 보여 줍니다 — ROOT_DIR 을 바꾸면 이 그림도 같이 바뀝니다. 접견(MEET)과 전화(PHONE)는 ② 까지 경로가 다릅니다 — 전화는 XVARM 브로커를 타지 않습니다.
① 처리 구간 모드 — 2트랙 드롭다운을 바꾸면 서버 재시작 없이 즉시 전환됩니다
디렉터리
ROOT_DIR
ROOT_DIR 은 OS 로 자동 감지 — Windows C:/k8s/voice_collector, Linux/K8s /k8s/voice_collector. 표준 배치: xvram/original_voice_files · esb/meet · esb/phone · xvram/decoding · xenon/meet/{execId} · xenon/phone/{execId} (없으면 자동 생성). ESB 수신(접견) 폴더는 로컬 브로커의 BROKER_OUTPUT_DIR 과 같아야 합니다 — [브로커 연결 확인] 으로 대조.
연동 상태 — DB · 브로커 · 로그 컬렉터 배치를 돌리기 전에 여기서 먼저 대조하십시오
두 경로가 어긋나면 브로커는 "추출 완료" 를 돌려주는데 수집기는 빈 폴더를 봅니다
② 제어
배치 4종 — 실제 REST API 를 호출하고 응답을 ③ 요약 바에 남깁니다. 시뮬레이션 데이터는 접견 7·전화 7 = 14건(트랙별 일배치 5 · 10분 주기 2)
같은 배치를 두 번 실행하면 두 번째는 건너뜀으로 잡힙니다 — 주기배치 창이 겹쳐도 같은 음성을 다시 처리하지 않습니다.
③ 최근 배치 결과 —
아직 실행한 배치가 없습니다. ② 의 배치 버튼을 누르면 호출한 API 와 응답이 여기에 요약 바로 남습니다.
처리 대상
종류키파일명발생 시각 암호화기존 STT처리됨
④ 재처리(Retry) 시나리오 — 브로커 장애 → 실패 이력 → 복구 → 재처리 접견 트랙(REST 브로커) 기준 · 실패한 건은 멱등 표식이 없어 다음 배치에서 다시 처리됩니다
장애 주입 (Chaos)
STT 구간에 실패·지연을 섞습니다
